# Правила работы с учебными задачами


- Не предлагай подсказки, алгоритм или готовое решение без запроса пользователя на помощь или проверку.
- Просьба проверить решение разрешает оценить его корректность, но не разрешает выдавать исправленный код или готовое решение.
- Если решение неверно, сообщи об этом и начни с одной небольшой подсказки или наводящего вопроса. Не раскрывай сразу причину полностью, способ исправления или ключевой приём.
- Давай подсказки постепенно: после каждой оставляй пользователю возможность подумать и попробовать самостоятельно. Не выдавай всю цепочку подсказок за один ответ.
- Показывай готовое решение, исправленный код или полный разбор только по явной просьбе пользователя, например: «покажи решение», «исправь код» или «объясни полностью». Просьба «дай ещё подсказку» такого разрешения не даёт.
- Если решение верно, можно подтвердить это и кратко объяснить, почему оно работает. Не добавляй альтернативные решения и улучшения без запроса.
- Не изменяй код учебных решений без явной просьбы пользователя.

## Коммиты и публикация

- Пользователь разрешил публиковать этот проект в публичном GitHub-репозитории и самостоятельно делать коммиты и отправлять изменения без повторного подтверждения.
- Делай коммит и публикуй накопленные изменения после завершения примерно 2–3 крупных или средних паттернов либо 5 небольших. Для смешанного набора выбирай сопоставимый по объёму этап по своему усмотрению.
- Считай паттерн завершённым после проверки корректности; промежуточные попытки не считай завершёнными паттернами. Перед публикацией проверяй состав изменений и не включай секреты и посторонние файлы.
- Для операций с GitHub используй только GitHub MCP. Не заменяй его на GitHub CLI, прямые HTTP-запросы или сетевые команды Git без явного разрешения пользователя. Если нужного инструмента нет, сообщи об ограничении.
- Пиши содержательные сообщения коммитов и после публикации кратко сообщай, что опубликовано.
- Репозиторий: `https://github.com/irhinandrej399-jpg/async-patterns`, основная ветка `main`, remote `origin`.
- Пользователь отдельно разрешил браузер для создания репозитория и локальный Git для привязки папки и синхронизации опубликованной истории. Публикацию коммитов выполняй через GitHub MCP.
- Первая публикация должна сохранить исходное состояние проекта; `predictable behavior` пока в работе и не считается завершённым паттерном. После первой публикации отсчитывай завершённые паттерны для следующего коммита.
